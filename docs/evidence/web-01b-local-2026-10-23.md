## Sửa CI: lockfile thiếu `libc` (PR #37, 2026-10-23)

Application CI (`s1-local`) fail ở `scripts/verify-toolchain.sh` → `npm ls --all`:
`invalid: lightningcss-linux-x64-musl@1.33.0`. Nguyên nhân:

- `vite` 8.3.0 cần `lightningcss ^1.33.0` (cấp gốc), còn `@tailwindcss/node` 4.3.3 pin `1.32.0` (lồng bên trong).
- Lockfile (phần `vite`, có từ PLT-01) thiếu `libc` ở 10 entry Linux: `@rolldown/binding-linux-*@1.2.9`,
  `lightningcss-linux-*@1.33.0`; registry có khai báo `libc`. Runner glibc vì thế cài cả bản musl 1.33.0.
- Bản musl đó che dependency tuỳ chọn `lightningcss-linux-x64-musl@1.32.0` của bản lồng → `npm ls` báo `invalid`.
- Trên Windows cả hai bản musl đều bị bỏ qua nên local không thấy lỗi.

Sửa: bổ sung `libc` đúng theo registry cho 10 entry đó (+30 dòng, chỉ trường `libc`, đúng vị trí npm ghi). Tạo lại bằng
npm (`--package-lock-only` hoặc `npm install` sau khi xóa entry) không dùng được: npm không resolve lại entry đã xóa và
làm mất binary của nền tảng khác.

| Kiểm tra | Kết quả |
|---|---|
| Lỗi CI tái hiện trước khi sửa: `npm ci --os=linux --cpu=x64 --libc=glibc` + `npm ls --all` trên bản sao | FAIL Linux glibc và musl (đúng thông báo CI); PASS Windows, macOS |
| Sau khi sửa, cùng kiểm tra cho linux-x64-glibc, linux-x64-musl, win32-x64, darwin-arm64 | 4/4 PASS; glibc chỉ cài `-gnu`, musl chỉ cài `-musl` |
| Audit `libc` của mọi entry Linux trong lockfile so với registry | 0 sai lệch |
| Linux thật (WSL Ubuntu 22.04, glibc 2.35, Node 24.21.0): `npm ci --ignore-scripts`, `npm ls --all`, `npm install` (lockfile không đổi), `npm ci`, typecheck, test, build | PASS; 52 test |
