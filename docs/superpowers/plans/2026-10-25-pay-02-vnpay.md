# PAY-02 VNPay Sandbox Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** payment-service tạo link VNPay PAY 2.1.0 đã ký, nhận IPN, query QueryDR và áp kết quả đã xác minh một lần; chạy được với VNPay sandbox thật trên local.

**Architecture:** Package mới `vn.fashion.payment.vnpay` (ký, cấu hình, client QueryDR, controller public, worker) bên cạnh `payments` hiện có. `PaymentService.create` thêm nhánh VNPAY (không gọi mạng); một hàm `VnPayResults.apply` dùng chung cho IPN và QueryDR, chạy trong transaction với advisory lock theo order như PAY-01. Gateway thêm một route public cho hai path VNPay.

**Tech Stack:** Java 21, Spring Boot 4 (`RestClient`, `@Scheduled`), JDK `javax.crypto.Mac` HmacSHA512, PostgreSQL Testcontainers, Spring Cloud Gateway, bash + Node (ký service token local).

**Spec:** `docs/superpowers/specs/2026-10-25-pay-02-vnpay-design.md` (đã duyệt 2026-10-25). Đọc spec trước task đầu tiên.

## Global Constraints

- `vnp_Version=2.1.0`, `vnp_Command=pay`/`querydr`, `vnp_CurrCode=VND`, `vnp_OrderType=other`, `vnp_TxnRef = order_no`, `vnp_OrderInfo = "Thanh toan don hang {order_no}"`.
- `vnp_Amount = Math.multiplyExact(amount, 100)`; ngày `yyyyMMddHHmmss` theo `Asia/Ho_Chi_Minh` (GMT+7).
- Chữ ký link/IPN: tham số `vnp_*` khác rỗng trừ `vnp_SecureHash`/`vnp_SecureHashType`, sort tên tăng dần, `name=URLEncoder.encode(value, US_ASCII)` nối `&`, HMAC-SHA512 hex chữ thường; so sánh bằng `MessageDigest.isEqual`.
- QueryDR request checksum: `RequestId|Version|Command|TmnCode|TxnRef|TransactionDate|CreateDate|IpAddr|OrderInfo`; response: `ResponseId|Command|ResponseCode|Message|TmnCode|TxnRef|Amount|BankCode|PayDate|TransactionNo|TransactionType|TransactionStatus|OrderInfo|PromotionCode|PromotionAmount` (thiếu = rỗng).
- IPN luôn HTTP 200 JSON `{"RspCode","Message"}`: `00` Confirm Success, `01` Order not found, `02` Order already confirmed, `04` invalid amount, `97` Invalid signature, `99` Unknow error.
- Secret chỉ từ env (`PAYMENT_VNPAY_*`, spec §2); không log, không vào DB/evidence/fixture. Fixture dùng secret giả lập `TEST-HASH-SECRET` và TmnCode `TESTTMN1`.
- Local: biến VNPay nằm trong `infra/local/.env` (đã gitignore, local-up đã dùng) thay cho file riêng `vnpay.local.env` của spec §2; Task 5 sửa spec cho khớp.
- Không thêm dependency; không đổi order-service/storefront; VNPAY tắt khi `PAYMENT_VNPAY_TMN_CODE` rỗng (CI).
- Comment code theo mẫu `// TASK:PAY-02: ...`; commit thẳng trên `dev`, không push.
- Lệnh test Java: `./mvnw -pl services/payment-service -Dtest=<Class> test` (cần Docker). Máy 7.4 GB: chạy từng class, không chạy cả reactor.
