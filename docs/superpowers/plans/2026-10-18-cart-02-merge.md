# CART-02 Merge Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `POST /api/v1/carts/merge` gộp giỏ guest vào giỏ member đúng một lần, báo adjustments.

**Architecture:** `CartMergeService` trong package `cart`: đọc giỏ guest (ACTIVE hoặc MERGED) + gọi catalog/stock
ngoài transaction; một transaction: idempotency → lock hai giỏ theo id → already-merged / version → ghi items →
MERGED. Route trong `CartController`.

**Tech Stack:** Java 21, Spring Boot 4.0, JdbcClient, Testcontainers; catalog/inventory là `StubServers`.

**Spec:** [CART-02 design](../specs/2026-10-18-cart-02-merge-design.md)

## Global Constraints

- Bearer bắt buộc (401 `INVALID_ACCESS_TOKEN`), cookie guest bắt buộc (thiếu/sai → 404 `CART_NOT_FOUND`).
- `Idempotency-Key` bắt buộc; scope `user:<id>`, operation `cart.merge:<guest_cart_id>`.
- Body `guest_cart_id`, `guest_expected_version`, `member_expected_version` (bắt buộc, ≥ 0).
- Adjustment reasons `UNAVAILABLE|OUT_OF_STOCK|QUANTITY_CAPPED|CART_ITEM_LIMIT`; response xóa cookie (`Max-Age=0`).
- Không gọi HTTP trong transaction; không migration.

## Review Focus

- Merge khi member đã có cùng variant với qty > available → không giảm qty member — Task 1 `memberQuantityNeverReduced`.
- Giỏ guest rỗng → 200, guest MERGED, member version +1, adjustments [] — Task 1 `emptyGuestCart`.
- Cookie hợp lệ nhưng `guest_cart_id` của giỏ khác → 404 — Task 1 `otherGuestCartIs404`.
- Retry key khác sau merge → `already_merged`, không gọi dependency — Task 1 `retryOtherKeyAfterMerge`.
